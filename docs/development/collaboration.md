# 协作与执行规范

本规范承接简短的 `AGENTS.md` / `CLAUDE.md`，适用于人工与 AI 协作者。默认中文沟通与文档记录，称呼项目所有者为「萝卜SAMA」。

## 任务启动与实施

1. 检查工作区、分支、暂存区与远端跟踪状态，区分本次任务、已有改动和并行改动；不覆盖、回退或顺手提交无关内容。
2. 判断任务是说明、诊断、设计、实现、治理还是发布，只读取所需专题。涉及当前阶段或下一步，先读[当前规划](../planning/current.md)。
3. 查找现有实现、命名、文档和验证入口，在既有职责内修改，避免平行配置、演示副本及无关重构。
4. 范围明确、风险可控且已授权时直接完成；共享 API、token 语义、依赖、架构或发行范围实质变化时，先说明影响并确认。已明确授权的普通实现、文档同步和验证不重复询问。
5. 抽象服务于真实复用和边界隔离；错误要可观察，不吞异常、伪造成功或用占位结果冒充能力。

代码和文档命名应表达实际职责；优先使用明确类型、直接函数和标准能力，不用隐式全局状态、动态魔法或多层转发掩盖边界。源码体量按内聚职责拆分，不从兄弟项目照搬行数门禁。仓库文本与文件名遵循根入口和 `.editorconfig`；生成物注明输入和生成入口，测试与示例使用合成或脱敏内容。

## 操作与授权

任务范围内的文件读写、只读 Git 检查、静态检查、构建和现有测试可直接执行。本地提交依据当前任务授权，精确暂存路径；不修改当前用户 Git 身份、不附加 AI 署名。

安装或调整依赖、启动长期服务、推送、远端设置、发布包、tag / Release 和部署，需要当前任务对应授权。说明具体目标、命令或差异、主要副作用及必要清理；已获同范围授权继续执行。读取兄弟项目不包含跨仓写入或搬入代码 / 资产的授权。禁止破坏共享历史、擅自清理用户数据和修改全局配置。

启动展示站时说明端口和停止方式；验证结束停止本任务启动的进程。不要在日志、截图、fixture、提交或聊天中暴露有效凭据和个人数据。沙盒提权不能代替任务授权。

`master` 已接 Vercel 生产部署，因此合并到主线本身有部署副作用；授权时明确说明，不能套用“合并不部署”的通用模板。组件包发行、DNS 和托管设置仍分别判断范围。

## 文档职责

| 位置 | 唯一职责 |
| --- | --- |
| `AGENTS.md` / `CLAUDE.md` | 跨任务、跨阶段、读取专题前必须生效的少量约束和路由 |
| `docs/architecture/`、`docs/development/`、`docs/features/` | 稳定边界、实施契约、验收规则 |
| `docs/adr/` | 重大长期决策、原因、代价与替代关系 |
| `docs/planning/roadmap.md` | 项目整体目标、范围、阶段、依赖顺序和出口 |
| `docs/planning/topics.md` | 大专题边界、子专题主要归属和唯一进度 / 验收来源 |
| `docs/planning/current.md` | 当前范围、顺位、临时门禁和停止线 |
| `docs/devlogs/` | 按 Asia/Shanghai 日期记录实施、验证、失败与限制 |
| README 与文档索引 | 定位、导航和必要摘要，不复制整套规则 |

文档与代码、模板或远端状态冲突时，先判断哪方过期，在本次范围内统一；不靠放宽检查掩盖漂移。小修复复用既有专题，不强制另建计划；状态、规则和证据各有一个来源。根入口正文保持同步，内容以可读、可路由为准，不机械移植兄弟项目的目录规模和篇幅门禁。

## 三级规划与唯一进度来源

采用“项目整体规划 → 大专题 → 子专题”组织规划与进度。阶段表示交付顺序，专题表示能力边界，不因跨阶段或跨平台再建一份相同任务。大专题目前在[专题地图](../planning/topics.md)稳定章节维护；已有专题路径不强制搬迁，规范、ADR、运行手册和历史记录作为来源引用，不强行包装成功能规划。

- 整体规划维护价值、范围、依赖、阶段出口和长期非目标，不复制详细任务状态。
- 大专题明确用户价值、能力边界、设计来源、依赖、子专题及整体完成条件。远期只登记启动条件，不虚建空子专题。
- 子专题明确一个主要归属、必要协同、具体场景、输入输出、已存在基础、依赖、正常 / 失败 / 恢复路径、实施项、验收方法与证据限制；小专题可合并章节，复杂子专题可分期交付。
- 每个任务只有一个主状态来源，默认就在所属子专题。跨专题集成引用原任务和证据；切片是子专题内部实施粒度，不递归成第四层规划或平行任务库。
- 方案状态使用草案 / 已确认 / 已替代；实施状态使用待开始 / 进行中 / 待验收 / 已完成，阻塞与暂停另外注明原因。工程预览完成、视觉批准、目标平台验证、产品采用及发布分别判断。
- `current` 汇总活跃范围、阻塞、下一步和停止线；地图只路由。验收标准归正式专题，结果在开发记录绑定源码 / 环境 / 输入 / 实际结果 / 未覆盖面，不按文档数量或勾选比例报告完成度。
- 新增、调整或完成专题时，同批核对主要归属、依赖、状态 / 验收来源、current 与证据。历史已完成基线保持原身份，整理索引不代表重开任务、改变排期或扩大操作授权。

## 组织成员与 AI 协作

其他组织成员及其使用的 AI 从最新远端 `dev` 建各自主题分支，验证后向 `dev` 发 PR；不同成员或任务不共用一个写入分支。提交前理解正在修改的组件与调用关系，PR 中说明起点和同步情况。具体命令、并发更新及合并责任见[仓库治理](repository-governance.md#组织成员的分支流程)。

萝卜SAMA本人或明确授权执行同一串行维护任务的 AI 可直接在 `dev` 推进；这不是组织成员的默认权限。发现其他成员并行写入或工作区状态变化时先判断归属，不能用 reset、清理或覆盖操作消除冲突。需要隔离才新建本地工作区，跨仓仍默认只读。

## 验证与交接

开发中按影响执行定向检查；稳定晋级前执行 `npm run build` 并补齐相关交互与视觉验收。检查入口和 CI 契约见[仓库治理](repository-governance.md)，桌面、窄屏、明暗和状态矩阵见[设计系统契约](design-system.md)。

每次交付说明改动、实际命令 / 结果、未验证面与遗留风险。构建、视觉批准、跨平台验证、真实产品接入和发布部署分别判断，不相互代签。重要规则变更及批次验证写入本周记录；不把尚未运行的 CI 或未启用的远端规则写成完成。

## 根入口维护判定

一条规则只有跨任务成立、跨阶段成立、读取专题前必须立即生效，并且无法仅通过任务路由可靠承载时，才进入 `AGENTS.md` / `CLAUDE.md`。详细实施方法进入本规范或对应专题；当前状态、临时门禁、具体批次和长命令输出进入 current 或开发记录。两份入口只允许标题和入口说明不同，正文同步并通过仓库检查；补充细节以避免真实协作遗漏为目标，不以行数等同完整性。
