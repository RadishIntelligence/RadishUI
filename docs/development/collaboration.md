# 协作与验证

采用家族通用协作方式的轻量版本：规则保持清楚，自动化随实际实现增加。

## 分支与提交

- `master`：稳定主线；`dev`：日常开发和集成。
- 普通串行任务在 `dev` 直接推进；需要并行、外部评审或风险隔离时才建主题分支。
- 初始工程作为共同基线提交到 `master`，从同一提交建立 `dev`；后续稳定晋级通过 `dev → master` PR。
- 单人阶段不要求额外审批人；主线合入后将主线回流 `dev`，保留共同历史。
- Conventional Commits，按主题提交；不添加 AI 署名，不覆盖现有工作，不 force push。
- 当前没有配置远端保护或 CI；以上为协作约定，不代表服务端已强制执行。

## 验证入口

| 命令 | 覆盖 |
| --- | --- |
| `npm run check:repo` | 协作入口同步、必要文档、文本编码、JSON |
| `npm run check:tokens` | JSON 与生成 CSS 对应 |
| `npm run type-check` | React 组件、展示站和 Vite 配置类型 |
| `npm run build` | 上述检查与静态构建 |

涉及展示与组件视觉时检查至少一个桌面和一个窄屏，覆盖适用的明暗、键盘焦点、禁用、加载与长内容。截图和脚本通过不自动构成视觉批准。

## 变更与发行

共享 API、token 语义和默认视觉变化需要说明影响、采用范围和验证证据。产品通过明确版本接入；当前 workspace 内部使用不等于已发布。

正式许可、公共包名、版本策略、CI 与发布流程随实际首批接入确认，不提前搭建无真实检查的门禁。
