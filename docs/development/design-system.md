# 设计系统变更与接入契约

RadishUI 服务多个产品，统一视觉决策、组件语义和关键状态。当前具体能力以[架构](../architecture/overview.md)和[当前规划](../planning/current.md)为准；本文规定能力增长时的边界，不把规划写成已实现支持。

## 通用与产品的分界

- 通用基础负责颜色语义、尺度、字体层级、密度、交互状态、可访问性及平台组件。
- 产品负责接口、身份与权限、业务状态、领域模型和路由；组件使用 props / callback 表达通用输入输出，不引用产品运行时。
- 页面范例展示导航、列表详情、表单、阅读与反馈模式，使用真实共享组件；示例数据留在展示站。不得为展示效果维护组件的第二份实现。
- 新能力先说明复用场景，再进入共享包；产品专用能力留在产品侧，不因已有一份实现就整包提升。

## token 与平台

`packages/tokens/src/tokens.json` 是机器来源；通过 `npm run tokens:generate` 生成 CSS 并核对 `npm run check:tokens`。来源和精确纳管的 `packages/tokens/dist/tokens.css` 一起提交，不手改生成物。不把当前最小 JSON 格式称为完整 DTCG 支持。

React 与 Flutter 分别实现，保持颜色角色、层级、状态含义及关键反馈对应，遵守各平台交互习惯；不要求共享组件源码或像素级一致。新增 Dart、其他平台产物或 token 层级时，先确认格式、消费路径和生成责任。Godot / egui / 自绘环境根据真实需求单独适配，不自动进入 React / Flutter 的运行依赖。

主题通过正式 token 与组件变体表达。产品的直接 CSS 覆盖只作为有范围、原因和退出条件的例外，不默认为共享 API。已有 family-ui 和产品样式是参考输入，迁移需逐项识别来源、授权、通用语义及保留的产品行为。

## 同类控件的尺寸与复用

- 同一视觉模式只允许一个共享实现和一组共享尺寸变量；页面通过 `size` / variant 等语义参数选择尺寸，不得用页面 CSS 改 padding、font-size、height、radius 或覆盖共享变量。
- 分段控件（Tabs / ToggleGroup）由同一组 `--rd-segmented-*` 变量驱动。`md`（导航 tabs）：list padding 4px、item 28px、item padding 4px 10px、font 13px、line-height 1.5；`lg`（工具条控件/筛选）：list 0、item `--rd-control-height`（桌面 32 / 移动 36）、item padding 0 10px、font 13px，与 Select / Button 同高、同字级；`sm`：list 2px、item 24px、item padding 2px 8px、font `--rd-font-size-xs`。工作台按上下文传 `size="md"` 或 `size="lg"`，页面只传 `size`。
- 页面组合必须使用 PageHeader / Section / Segmented / Table / Pagination / TOC 等页面原语；尺寸、间距、分割线与卡片内边距由原语/变量决定，页面不写一次性尺寸。
- 内容与分割线之间至少 16px（`--rd-space-4`）；分割线属于区块边界，不能紧贴文字或导航。
- 视觉验收必须比较同一组件在不同页面的同一视口、同一缩放下的计算值（宽、高、padding、font-size、line-height），并检查分割线/卡片间距；页面级尺寸覆盖没有书面例外不得合入。
- 确实需要不同尺寸时，新增/使用共享 `size` 变体并同步 token/契约，不在页面内写死。

## 变更评审

具体设计判断按[设计条例与约束](../design/design-rules.md)引用已确认的默认原则、例外和待审参考建议；后者不自动升格为家族强制规范。条款不替代本文的来源、兼容性与真实交互验收要求。

| 变化 | 必须说明 |
| --- | --- |
| token 删除、改名、角色或默认值变化 | 消费位置、明暗对应、视觉影响和迁移 |
| props / 事件 / 导出变化 | 兼容性、默认行为、键盘与焦点、失败或边界状态 |
| 默认视觉、密度、排版变化 | 组件及代表页面前后对照、长中文 / 长名称、窄屏影响 |
| 新平台、运行时或依赖 | 来源、版本、许可、打包与支持范围；实际验证平台 |
| 第三方图标、字体、截图或设计 | 原始来源、作者 / 许可、采用范围、署名要求 |

新增组件应说明可访问名称、键盘行为、焦点处理，以及适用的默认、hover、active、focus、disabled、loading、error、empty、readonly 状态。纯展示组件可标明不适用，不能以缺省实现代替状态设计。

## 验收与证据

- 自动化：使用根 `package.json` 的检查 / 构建入口；新增实际行为时增加能发现回归的测试，不以重复实现细节的测试凑覆盖率。
- 视觉：至少桌面和窄屏、亮暗主题；检查适用状态、溢出、长内容、缩放及键盘焦点。记录视口、主题、浏览器、源码 SHA 或工作区状态、实际结果与未覆盖内容。
- 页面：共享组件在真实长度内容和组合场景中检查；组件陈列通过不能代替代表页面或产品接入验证。
- 批准：运行截图与自动比较只提供证据，家族视觉基准由萝卜SAMA确认。未批准的工程预览不能成为家族强制视觉标准。

设计探索可将自有合成候选保存到 `designs/` 与 `assets/design-baselines/candidates/`，附原生 frame、变量、范围及未批准身份；不能用候选充当正式基准。本仓对外部受限参考只纳管公开元数据，所需副本放在获准的仓库外私有库；本仓研究不自动授权移动来源文件或切换产品入口。来源与采用边界见[家族设计资料](../design/README.md)。

截图等临时验证输出放在忽略目录 `output/`，开发记录引用路径与结论；正式基准需要先确认来源、采用范围和固定运行环境，再明确纳入版本管理。`.pen` 只能通过 Pencil 读写，不用文本工具读改或生成。

## 版本、产品采用与回滚

当前内部 private workspace 不等于已发布 npm / pub 包，也不承诺 React 18、Flutter 或其他消费环境兼容。版本策略已确认为家族日历版本，npm 版本为 `YY.M.RELEASE`，详见[版本策略](versioning.md)。正式发行前仍先确认许可证、公共包名、构建 / 类型导出、支持矩阵和发布门禁。

产品以明确版本或固定提交采用，记录采用组件、平台、主题 / 变体、例外、验证和回滚目标。共享库变更通过产品升级生效，不自动改写所有产品，也不以浮动最新依赖绕过审阅。API、token 语义和默认视觉可能分别产生迁移成本，不能仅凭 TypeScript 编译成功判断无破坏。
