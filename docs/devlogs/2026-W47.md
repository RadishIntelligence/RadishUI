- 选择理由：三项都落在已有真实页面（全局 Toast、资源库 R1），只改焦点、可访问名称与 ARIA 语义，不新增共享 API、不改 token、不动布局与页面原语；符合「不补没有页面承载的空壳 API」和「组件数量不作为完成度」的当前原则。G9 InputOTP 无真实页面承载，G10 / G11 需要视觉裁定，未进入本批。
- **G6 Toast**：Radix 的 `role=region` 在 `<ol class="rd-toast-viewport">` 的父层，区域名原先只由 Provider 的 `label` 承担播报，viewport 仍使用默认英文 `Notifications (F8)`。改为给 `ToastPrimitive.Viewport` 传 `label={`${label} ({hotkey})`}`，由 Radix 替换 `{hotkey}`；中文实测「通知 (F8)」，英文 App 实测「Notification (F8)」。Provider 的播报文本保持 `label`，不把 F8 混入朗读句。
- **G6 焦点归还**：Radix 在关闭前会把焦点放到 viewport，之前没有共享层归还逻辑，关闭后焦点留在空的不可见区域；App 又用 `key={notice.id}` 重挂载 Toast，实例内记录会丢失。现在打开时记录打开控件（优先 `document.activeElement`，鼠标点击场景由模块级 `pointerdown` 记录兜底，覆盖 macOS Chrome 点击按钮不聚焦），首次以 F8 / Tab 进入提示时记录进入前位置；关闭且焦点仍在提示内或已丢失时，优先回到打开控件，其次回到进入前位置，两者都不可用（如保存后按钮变为 disabled）时把焦点移出空 viewport。自动消失且用户已在别处操作时不抢焦点；`prefers-reduced-motion` 下同样成立。
- **G6 焦点环**：`.rd-toast-viewport:focus-visible` 与 `.rd-toast:focus-visible` 分别补 1px `--rd-focus-ring`、4px / 2px 偏移；浅色实测 `rgb(59, 107, 140)`，深色 `rgb(169, 201, 227)`。减少动效规则不变。所有者复审截图指出关闭按钮的聚焦环与胶囊右缘几乎重叠；按反馈把胶囊右内边距由 7 提到 11px（关闭按钮左侧的文案间距保持 10px），焦点环右侧余量约 8px、上下约 4px，关闭按钮左右间距接近对称。浅色 / 深色 / 390 与 2x 截屏复验，页面无横向溢出。
- **G7 空结果播报**：R1 空态本身没有 `role` / `aria-live`，分页的「共 N 项」`role=status` 又在空结果时卸载，导致筛选无结果没有任何播报。在资源工具栏后增加常驻 `sr-only` `role="status"`：无结果时播报「没有匹配的资源」，资源为零时「还没有资源」，清除筛选后清空；空态视觉块不加第二个 live region，也没有新增 EmptyState 共享组件。
- **G8 移动选中态**：移动资源按钮补 `aria-pressed`，与桌面表格按钮同语义；`li` 不加 `aria-selected` / `aria-current`，避免与按钮语义混用。视觉高亮、详情抽屉和桌面行为不变。
