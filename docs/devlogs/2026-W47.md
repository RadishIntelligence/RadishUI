### 强制颜色与减少动效补验（Chrome）

- 按当前规划第 4 项，范围限定为 Chrome 的 forced-colors、`prefers-reduced-motion`、键盘焦点与 Batch A–F 回归；不安装新浏览器、不启用 Safari 远程自动化、不改共享 API / token / 页面结构。浏览器为系统 Google Chrome 157.0.8103.51，使用既有 Playwright 1.64.0-alpha npx 缓存（`channel: 'chrome'`），未新增仓库依赖。
- **强制颜色发现**：forced-colors 替换作者背景、边框与阴影后，① Select / Menu 的 `data-highlighted` 选项只剩同底色，键盘位置不可见；② tabs 与 ToggleGroup 的当前项背景、阴影被压平；③ 分页当前页与其他页码同底色；④ 侧栏当前项只剩 500 字重；⑤ 资源表选中行与移动选中项同底色；⑥ 开关选中态轨道与滑块都变白，单选选中点消失（复选框的勾仍可见，设置页主题卡有勾选标记）；⑦ 视觉基础 14 个色板与设置页三张主题缩略图全部退化为同色。Toast、Dialog、文档目录当前项、1px 焦点环仍可辨。
- **修复**：只追加 `@media (forced-colors: active)`，普通模式零改动。选项 / tabs / 分段 / 分页当前页 / 侧栏当前项改用 2px `Highlight` 描边（tabs / 分段补 hover 覆盖与 `transition: none`，避免 Chrome 过系统色过渡后回落为黑字）；开关用 `Highlight` 轨道与 `HighlightText` 滑块，复选与单选用 `Highlight` 边框 / 指示点；资源选中行用 2px 上下边框，移动选中项用描边；视觉基础色板与主题缩略图用 `forced-color-adjust: none` 保留原色。文字保持 `CanvasText`：本机 Chromium 的强制颜色模拟会把 `Highlight` / `Canvas` / `ButtonFace` 白字画成实心块，实测 `forced-color-adjust: none` 的白色文字正常，因此不使用白字填充方案。
