# 能力专题地图

本页连接[整体规划](roadmap.md)、大专题、子专题及唯一进度来源，不复制子专题任务状态。大专题在本文稳定章节中维护，子专题复用现有文档或单独成文；逻辑层级不要求目录强制搬迁。

架构、协作规则、设计系统契约和 ADR 是各专题引用的规范来源；当前顺位只在 [current](current.md)，日期化结果只在 [devlogs](../devlogs/2026-W45.md)。它们不是另一级功能规划，也不与子专题重复维护待办。

<a id="foundations"></a>

## F：视觉基础

用户价值：让颜色、尺度、排版和状态具有一致含义，平台产物能追溯共同设计来源。拥有 token 与正式视觉基准，不承接产品业务色彩规则。依赖真实代表场景及来源确认；向组件、页面范例和产品采用提供设计契约。

| 子专题 | 设计、实施进度与验收来源 | 协同 |
| --- | --- | --- |
| F-01 最小 token 来源与 CSS 管线 | [Token 基础](../features/token-foundation.md) | 组件消费、主题展示 |
| F-02 视觉基准与资料归集方案 | [视觉、代表页与资料归集提案](../features/visual-baseline-proposal.md) | C 首批组件边界、E 代表页与试点、G 跨仓迁移流程 |

正式视觉基准在 P1 根据已确认场景细化，F-02 先维护现状研究、本仓资料与代表页候选；先确认满意的第一版设计，再单独评估产品采用与跨仓资料切换。当前正文、索引与原生候选见[设计资料入口](../design/README.md)。依据[设计系统契约](../development/design-system.md)和[架构](../architecture/overview.md)约束来源与状态。完成条件是选定版本的 token 角色、亮暗对应、生成一致性、视觉确认及迁移影响均可复核；探索取值不能冒充家族定稿。

<a id="components"></a>

## C：跨平台通用组件

用户价值：产品直接消费已有的通用交互与样式，减少独立实现造成的偏差。拥有组件 API、状态、可访问性与平台实现；依赖 F 的设计基础，协同 E 的真实页面验收。业务数据、权限和路由留在产品侧。

| 子专题 | 设计、实施进度与验收来源 | 协同 |
| --- | --- | --- |
| C-01 React Button 工程预览 | [React Button](../features/react-button.md) | F-01、E-01 |

Flutter 仍按[预留边界](../../packages/flutter/README.md)等待真实试点、范围和产物格式确认；其他 React 组件也在确认场景后新增具名子专题。完成条件按选定组件 / 平台集合验收 API、键盘 / 焦点、关键状态、视觉和消费兼容，不能由首个 Button 推断全平台可用。

首批组件候选在 F-02 方案中协同确定；正式实现获准后归本大专题维护组件合同与状态，不在 F-02 再复制一份实施进度。

<a id="examples"></a>

## E：展示、页面范例与产品采用

用户价值：在完整内容和真实组合中确认共同体验，并让产品有明确的采用与升级路径。拥有展示入口、页面组合、视觉基准的运行场景和接入验收；依赖 F 与 C，托管能力由 G 提供。不维护共享组件的第二份演示实现。

| 子专题 | 设计、实施进度与验收来源 | 协同 |
| --- | --- | --- |
| E-01 独立展示站工程预览 | [展示与交互范例](../features/docs-preview.md) | F-01、C-01、G-02 |

代表工作台 / 设置页及首批真实产品采用在 P1 / P2 确认后细化；当前不虚列接入产品或已完成页面。完成条件是选定代表场景可运行、内容与状态可信，并有明确版本的视觉批准或真实产品采用证据；线上可访问只代表展示部署。

F-02 协调 R1–R3 的方案与来源；代表页实现和产品试点获准后归本大专题，继续以具体子专题作为唯一任务来源。

<a id="engineering"></a>

## G：工程协作与交付

用户价值：组织成员能按共同流程贡献，稳定主线与设计产物可检查、审阅、部署和回滚。拥有仓库治理、验证、托管及未来发行；为其余专题提供工程支持，不创造产品业务依赖。

| 子专题 | 设计、实施进度与验收来源 | 协同 |
| --- | --- | --- |
| G-01 仓库与协作治理 | [仓库治理](../development/repository-governance.md#实施与验收) | 全部专题；协作规则和 ADR 为规范来源 |
| G-02 展示站托管 | [部署说明](../deployment/hosting.md) | E-01；不承担组件包发布 |
| G-03 初始工程集成验收 | [初始化范围与历史验收](../features/bootstrap.md) | F-01、C-01、E-01；保留已完成基线身份 |

正式包发行在 P4 的前置决策成立后再形成子专题。完成条件按当前交付载体判断：本地基线、真实 CI、远端规则和部署分别有结果，版本发布需另行满足许可、兼容与回滚要求。其他组织成员开始协作不代表服务端保护已自动开启。
