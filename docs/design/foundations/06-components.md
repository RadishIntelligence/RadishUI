# 06 组件形态与语义

形态由任务倒推，组件 API 与行为另见[首批组件边界](../components/first-batch.md)。不从一份产品实现推断它已经具备共享组件所需的键盘、焦点或可访问性。

交互区域与静态展示按[DR-02](../design-rules.md#dr-02)区分，保留特殊需求或特殊设计的例外。成组入口可以共享独立底板，不要求逐项画成按钮；侧栏的具体判断见[已选择的导航方案](../design-rules.md#sidebar-navigation)。

- Button 区分主、次、危险与轻量操作。同一任务保留明确主动作；loading 与 disabled 有不同原因，图标按钮有可访问名称。
- 字段由 label、控件、hint / error 组成，错误就近说明原因与下一步，失败保留输入。单位紧贴值；placeholder 不承担唯一标签。表单的校验节奏、必填标识与候选控件见[表单可用性规则](../patterns/forms.md)。
- Checkbox 表示选择，Switch 表示开启状态，Tabs 切换同级内容。静态颜色不能替代受控状态和键盘合同。
- 状态标签采用短文字与低强度语义色。已就绪、草稿、只读、失败各自有含义，不把所有状态都画成成功胶囊。
- 列表与轻表格连续组织，标题优先，数值对齐，当前行与 hover 分开。没有真实需求时不加入全功能 DataGrid、KPI 卡或批量操作。
- Dialog / Drawer / Menu 共享浮层语义，但分别定义关闭、焦点进入与恢复、滚动和键盘。危险确认写明对象与后果，保留继续编辑等安全返回动作。
- InlineAlert 放在问题附近；Toast 用于非阻断结果，从顶部以胶囊提示出现，关闭按钮同时显示剩余时间并在悬停 / 聚焦时暂停，超时自动消失；必要错误不自动消失。Tooltip 只补充信息，不承载唯一必要说明。

空态解释原因与下一步，加载保留结构，失败保留可读快照并标记是否过期。禁用原因能被触控与键盘用户获取，不能只存在于 hover。

AppShell、PageHeader、设置分组与列表 / 详情先作为组合范例，不提前冻结为万能布局 API。领域数据、权限、HTTP 与路由由产品负责。
