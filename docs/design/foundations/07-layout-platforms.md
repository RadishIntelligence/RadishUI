# 07 布局与平台

| Profile | 主要判断 |
| --- | --- |
| Workbench | 单一主任务、连续列表 / 表单、辅助栏按需出现 |
| Content | 共享基础，调整阅读行宽、字号与内容节奏 |
| Brand | 展示性排版与有限品牌表现，不能替代真实产品工作面 |
| Game | 游戏视觉自主，必要状态与可读性原则保持对应 |

Content 是本次整理明确的布局分类，不是旧 family-ui 已有 Profile。Profile 不绑定产品名单，也不决定业务信息架构。

代表视口为桌面 1440×900、窄屏 390×844。资源桌面使用列表 / 详情，窄屏列表进入单一详情；设置按标签、控件与说明重排；阅读将页内目录改为按需入口。宽度变化时根据内容重排，不缩放桌面，也不默认产生横向滚动。

React 与 Flutter 分别实现，保持设计语义和关键状态对应，行为遵守平台惯例。egui / Rust、Godot、输入法候选窗与窗口壳只吸收必要原则，不自动纳入 RadishUI 支持矩阵。产品画布、游戏 HUD、流程与原生权限留在产品侧。

范例不用虚构权限、远程 API 或路由能力。触控、键盘、滚动、中间宽度、系统亮暗和缩放分别需要真实环境证据；12 张静态稿只覆盖所画组合。
