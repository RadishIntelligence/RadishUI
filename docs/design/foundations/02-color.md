# 02 色彩与主题

先定义角色，再定义明暗取值。产品品牌可以有自己的表现；共享状态的含义必须稳定。

| 角色 | 用途 | 不应用于 |
| --- | --- | --- |
| 内容面 / 导航面 / 柔底 | 内容承托、区域区分、低强度强调 | 用色块替代信息结构 |
| 主文字 / 辅助文字 | 正文、说明、元信息 | 通过过低对比隐藏必要说明 |
| 品牌 | 身份、少量识别 | 默认表达成功或危险 |
| 操作 | 主按钮、链接、当前导航 | 表达业务成功 |
| 选择 | 当前对象、当前选项 | 错误、只读或加载 |
| success / warning / danger / info / neutral | 完成、待处理、失败、说明、无倾向状态 | 装饰或产品品牌分工 |

Workbench 以近白暖中性为候选主面，暗色使用有层次的墨绿中性面；品牌延续灰玉，操作延续墨蓝。色值与对照见[候选稿](../patterns/workbench-v1.md)，尚未冻结为 token。

实底的前景必须成对定义。暗色亮操作底应配深文字，不能沿用浅色白字。状态文字与柔底分别校验；禁用、只读、草稿和危险各自写明原因。普通文字目标对比度至少 4.5:1，必要控件边界与可见焦点目标至少 3:1；不能以截图看起来清楚替代计算与实际检查。

运行时只有 [`packages/tokens/src/tokens.json`](../../../packages/tokens/src/tokens.json) 是机器来源。[历史 JSON / CSS](legacy-v26.7.3/README.md)是固定输入，含旧色阶和旧状态值，不要求与当前来源同步，也不得直接加载覆盖当前库。历史母板是选色经验，不代表产品必须分配某种颜色。

新增主题时同时检查文本、操作、状态、边界、焦点和浮层，不只翻转背景。主题首屏稳定、系统跟随和切换行为留待实现验证。
