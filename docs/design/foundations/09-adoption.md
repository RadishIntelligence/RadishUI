# 09 视觉与交互验收

先用完整代表页检查结构，再看局部控件。逐项记下实际结果与未覆盖面，不用“构建通过”代替视觉或产品采用批准。

1. 来源：明确自有、第三方、受限与私人边界；参考学习点及排除项可追溯。
2. 结构：主任务明确，连续内容主导，辅助区有职责，没有卡片嵌套或无用途外框。
3. 色彩：品牌、操作、选择和状态分离；明暗下文字、实底前景、必要边界与焦点通过对比检查。
4. 内容：中文 / English、长名称、代码 / 路径、数值 / 单位可读，状态不被挤压。
5. 布局：桌面、窄屏和中间宽度，长内容、滚动、大字号 / 200% 缩放分别检查。
6. 状态：适用的默认、hover、pressed、focus、disabled、loading、error、empty、readonly 和未保存；失败保留输入与重试入口。
7. 交互：键盘顺序、焦点、可访问名称、浮层关闭 / 焦点恢复、触控区域与减少动态效果。

Pen 的布局问题扫描与静态预览只用于设计 QA。真实浏览器、辅助技术、Flutter 和产品验收仍需实现后验证。正式基准由萝卜SAMA确认，候选图不能变成默认批准。

设计候选及导出放 `designs/` 与 `assets/design-baselines/candidates/`；临时运行截图放忽略的 `output/`。批准后登记来源、版本、环境、视口、主题和变更原因，再迁为正式基准。
