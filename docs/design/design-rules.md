# 设计条例与约束

更新日期：2026-11-07。本文件统一记录 RadishUI 的具体设计判断、适用条件和参考依据，供画稿与页面评审使用。优先适用于 Workbench、设置和阅读场景；产品业务、平台行为、组件 API 与 token 来源仍按[设计系统契约](../development/design-system.md)处理。

## 规则身份与例外

| 条目 | 身份 |
| --- | --- |
| DR-01 / DR-02 | 萝卜SAMA本次明确确认的默认原则，均允许特殊需求或特殊设计的例外 |
| DR-03 / DR-04 | 此前反馈明确的密度与风格方向，具体数值仍是候选 |
| DR-07 的侧栏与目录方案 | 所有者已选择侧栏独立底板、连续列表、当前项高亮，以及目录整体区域、按正文标题分级；已同步相应桌面明暗候选，整体视觉仍待评审 |
| DR-05 / DR-06 / DR-08–DR-14 | 从 ref-01–29 提炼的设计建议，待随代表页评审；不是所有者已经逐条批准的家族规范 |
| DR-15 | 所有者本轮明确确认的工作台页面滚动偏好，默认适用于以扫描 / 操作为主的工作面；阅读、设置等特殊设计允许例外 |
| DR-16 | 所有者明确要求把响应式与输入方式适配纳入设计原则；适用于共享页面、组件和运行版验证 |

既有[设计原则](foundations/01-principles.md)、组件语义和可访问性要求继续有效。参考建议补充具体取舍，不降低既有要求，也不因写入本文就冻结视觉、发行 token 或切换产品。

特殊需求或特殊设计可以采用例外：在对应页面 / 组件说明中记录适用对象、实际原因与范围，并保留必要的识别和操作能力；沿现有设计评审处理，不另设审批层级。一次例外不自动成为其他页面的默认方式。

## 已确认的默认原则

<a id="dr-01"></a>

### DR-01 标题下尽量不放描述性文字

页面标题、区域标题、分组标题、工作区名称等类似标题的元素，下方尽量不放泛泛的描述性文字。名称、层级和相关内容应足以说明当前位置与任务，避免为每个标题配置一句副标题。

特殊需求或设计可以保留，例如首次设置向导的必要指引、错误恢复的下一步、危险操作的影响说明。文字须解决具体问题，并靠近相应任务；不能只为填补空白或重复标题。

文章导语、章节正文、字段帮助、资源摘要和账号角色按内容职责保留。它们是否需要出现，由实际信息价值判断。

| 场景 | 默认处理 | 例外依据 |
| --- | --- | --- |
| “资源库”“外观与偏好” | 只显示标题，不追加泛泛介绍 | 页面确有不能由名称与内容说明的使用前提 |
| 工作区名称、区域分组名 | 名称与必要状态即可 | 需要识别环境、范围或身份的具体差异 |
| 删除确认、首次设置、恢复失败 | 保留必要说明 | 说明直接影响用户的选择或下一步 |

<a id="dr-02"></a>

### DR-02 静态可平铺，交互尽量有可辨识的承托

类似只读展示的文字、参数、属性和小列表，可以直接平铺在背景中。可交互的区域或元素应尽量避免与普通背景融为一体，默认通过底色、边界、轻微抬升或清楚的控件 / 链接样式表达可操作性；特殊需求或特殊设计允许例外。

这一要求可以在单个入口或明确的交互分组上成立，不要求每个可点击元素都单独画成带边框按钮。导航、分段选择等可以共享独立底板；仅仅处于一个普通页面背景上，不足以说明已经形成交互分组。

| 对象 | 处理 |
| --- | --- |
| 只读属性、参数、时间、小列表 | 连续排布，靠排版、对齐和必要分隔组织 |
| 账号、工作区切换、独立动作、菜单触发 | 有清楚的底色 / 边界或适度抬升，入口范围可识别 |
| 成组导航、分段选择 | 可以共享底板，整项可操作，当前项与必要状态明确 |
| 可复制的只读参数 | 参数保持静态展示，复制动作使用明确入口 |
| 正文链接、编辑区等特殊设计 | 按任务采用适合的链接 / 编辑样式，记录必要例外 |

当前项、hover、键盘焦点、按下和禁用分别设计；不能只靠悬停才让用户发现主要操作，必要说明也不能只放在 Tooltip。静态信息不因为需要强调就被画成可点击控件；只读与禁用也不混为一种语义。

## 已明确的密度与风格方向

<a id="dr-03"></a>

### DR-03 留白紧凑，大小服务于内容

常见控件左右内边距优先 8–12px，普通内容容器优先 12–16px；这些是当前候选参考，不是已发布 token。避免父子容器重复叠加 padding；较大留白用于真实的分组、主次和阅读层次。

字号、行高、图标与必要触控区保持可用。分页等操作区按自身内容确定高度，未占满视口的空间由数据区或页面布局处理，不以撑大控件内边距填空。细节见[空间与层级](foundations/04-space-shape-elevation.md)。

工作面默认由主要内容占满可用空间；确定目录等辅助栏的宽度与栏间距后，主内容自适应使用剩余宽度，页面只保留必要的基础内边距。不把关联栏之间的余宽挪成内容两侧的大留白；只有明确采用居中阅读等特殊设计时，才单独限定正文宽度。

<a id="dr-04"></a>

### DR-04 现代、微圆角与胶囊按职责分配

延续所有者明确偏好的美式、现代、微圆角、胶囊感。内容容器保持适度圆角；按钮、筛选、搜索、分段选择、状态等按职责采用胶囊。长表单和连续列表维持整齐的阅读边缘，不为统一形态把所有对象都画成同一种圆卡片。

表面层次、细边界、轻阴影与排版共同形成触感。[现代圆角候选](patterns/modern-rounded-v1.md)已作为本轮 Web 实施起点，运行时语义映射由 [F-01](../features/token-foundation.md)维护；设计变量不直接充当机器来源，具体参数继续随真实页面迭代，不等于正式发行规范冻结。

## 侧栏：按钮列表还是当前项高亮的导航列表

**已选择的方案：独立导航面板中的连续列表，当前项高亮。2026-11-04 按所有者要求同步到三代表页的桌面明暗候选；账号与工作区切换保留独立控件。该选择不等于整套视觉已经定稿。**

| 方案 | 适合的任务 | 在本项目的取舍 |
| --- | --- | --- |
| 每项独立的按钮形态 | 少量、彼此独立的动作，例如新建、导入或切换账号 | 入口突出，但连续页面导航逐项加边框会增加视觉碎片；不再作为本轮侧栏的默认形态 |
| 普通导航行，当前项高亮 | 稳定的页面目的地、功能分组与收藏入口 | 更适合资源库、文档、偏好设置；重点落在当前位置，分组与增减项目也更自然 |

所选方案按以下方式满足 DR-02，真实状态与键盘行为按 [C-02](../features/react-workbench-components.md) / [E-02](../features/workbench-preview.md)在实现中验证，不能由画稿推断：

- 侧栏整体或导航分组具有清楚的底板和区域边界，普通行在这一独立区域内连续组织。
- 每行保持统一的图标、文字、命中范围与对齐；整行可操作，不只允许点击小图标。
- 当前项始终有柔和高亮，配合图标 / 文字强调；hover 提供轻反馈，键盘焦点有独立轮廓，三者不混为同一状态。
- 收藏沿用导航行；账号、工作区切换和折叠等承担独立动作的入口保留自己的控件形态。
- 视觉形态与行为语义分别判断：页面跳转采用导航链接语义，触发动作或菜单采用按钮语义。

如果侧栏没有独立区域，或只剩难以判断是否可点击的文字，不满足这一方案的前提。反过来，也不为满足“交互要清楚”而把每一行都强制画成卡片。

## 文档目录：整体区域与标题层级

2026-11-04 按所有者反馈采用整体目录区域，去掉逐项胶囊。目录是共享底板内的连续章节入口，通过实际标题层级、缩进、文字权重和当前章节标识组织，不把每个标题都画成独立按钮或卡片。

同级标题对齐，子标题按正文的真实 H2 / H3 等关系逐级缩进；不为了展示层级而把同级章节改成父子关系。当前 R3 默认示例的三个章节均为同级，目录保持一致缩进；编辑后的子标题按实际内容生成。移动运行页提供整个目录区域的展开 / 收起，尚无逐级折叠章节树；长目录是否需要分支折叠按真实需求再评估。2026-11-05 移动运行版把目录改为轻量折叠行：不铺大面积灰色底板，文本 14px，展开后仍是连续章节列表并保留 44px 触控命中区。

当前章节以文字强调和侧边细标记区分，整行命中范围保留；hover、键盘焦点与当前章节分别处理，不能以选中标记替代焦点。只读文档属性仍可在目录区域之外平铺，不为视觉一致给每个参数添加容器。

## 工作台滚动与固定单屏

**DR-15（2026-11-05，所有者确认）**：以扫描、选择、浏览条目为主的工作台（资源列表、队列、检查表等）默认固定单屏——页面标题、筛选 / 工具栏、分页 / 底部操作保持可见，只有主内容区滚动。不要让整页滚动把分页、筛选或表头带走。

- 主内容区是唯一的主要滚动所有者；标题、工具栏、分页和底栏不随内容滚走。
- 表格 / 列表在自身区域内滚动，表头可以吸顶；分页保持在列表卡片或页面底部。
- 移动端同样固定标题、关键操作和底部导航，列表在两者之间滚动；弹层在自身最大高度内滚动。
- 阅读长文、设置表单等以连续内容为主的页面，可以选择整页滚动，或固定头部 / 目录 + 内容区滚动；同一页面只保留一个主要滚动所有者，避免外层与内层同时抢手势。
- 例外：内容高度远小于视口且不需要固定分页、画布 / 长图 / 打印视图等，应在对应页面记录原因。
- 验证：滚动时标题 / 筛选 / 分页是否仍可见；键盘焦点不被固定层遮挡；窄屏、大字号和极端矮视口下内容区是否仍可用。

2026-11-05 按所有者对资源库“翻页跑到顶部”的反馈，先在 E-02 资源库运行版落实；其他页面按任务逐步采用。固定单屏不能以把内容区压到不可用为代价；极端大字号或极矮视口应记录例外或允许页面整体滚动。2026-11-07 运行版补上这一退化的具体规则：资源库比较工作区可用高度与非列表内容高度，列表可保留高度低于约 8rem（随基础字号放大）时改为整页滚动，列表取消内部滚动、表头不再吸顶；正常字号、窄桌面与 1440×600 仍保持固定单屏。例外只作用于以扫描为主的工作台，不扩展到设置 / 文档等连续内容页。

## 响应式适配与输入方式

**DR-16（2026-11-05，所有者确认）**：响应式适配同时以可用宽度和输入方式（fine / coarse、鼠标 / 触屏）为条件。可用宽度决定页面与组件如何重排；输入方式只决定命中区、hover 和精度相关增强，不能用 `pointer` 媒体查询关掉与输入方式无关的紧凑尺寸。

- 断点按内容可用宽度设置，不以设备型号或 UA 命名；同一断点内先重排内容与操作，再压缩装饰和留白。
- 触屏可点击目标至少 44×44 CSS px；视觉可以更小，但命中区不能小于该值。鼠标可以更紧凑，但不能让触屏失去可点区域。
- 紧凑尺寸、间距、字号的覆盖必须写明 pointer 范围；底栏高度、内容底部避让、卡片尺寸等非 pointer 语义的布局，默认同时适用于 fine / coarse，并在 computed style 中核对。
- 验证成对覆盖 fine / coarse，以及 320 / 390 / 440 / 768 / 1024 / 1440 等关键宽度；同时检查 DPR 1 / 2 / 3、横竖屏、200% 文字、安全区、键盘焦点。响应式模拟器要确认 `matchMedia('(pointer: coarse)')` 的实际值，不能只看宽度。
- 例外只适用于 hover-only、拖拽、精细指针专属手势等确有输入方式差异的能力；必须保留触屏可完成的替代路径并记录。
- 回归同时记录宽度和高度。2026-11-05 移动底栏曾出现 `maxWidth` 已更新、`height` 仍为 72px：宽度规则已生效，高度规则却写在 `pointer: fine` 内；修复后紧凑档统一 52px，链接 50px（命中 ≥44px）。

<a id="dr-17"></a>

## 界面 chrome 统一尺度

**DR-17（2026-11-07，所有者确认）**：展示站外壳与页面 chrome 采用同一套视觉尺度，不再让页头、标题操作、tabs、搜索 / 筛选、侧栏入口和分页各占一档大小；后续新增的 chrome 元素沿用这一尺度，避免逐页漂移。

| 环境 | 可见控件 | 标签文字 | 页面标题 | 复合入口 / 间距 |
| --- | --- | --- | --- | --- |
| 桌面（≥800px） | 32px | 13px | 1.625rem（默认 26px） | 侧栏行 32px、工作区切换 36px、账号约 50px；分页 32px |
| 移动 / 窄屏（≤799px） | 36px | 12–13px | 1.5rem（默认 24px） | 页头 52px、tabs 列表 36px、分页 36px；组间距 8–12px |

- 页面标题用 rem，随基础字号一起放大；控件高度与命中区用 px，不随字号膨胀。
- 触屏命中仍然 ≥44×44：36px 的按钮、选择器和 tabs 用不可见的 `::after` 扩展命中区；搜索等文本输入由外层 label 提供 44px 命中。视觉缩小不改变 DR-16。
- 状态、禁用、焦点与 hover 继续由共享组件提供，不因统一尺度新增颜色或交互状态。
- 复合入口可以比单行控件高一档：工作区切换 36px、账号约 50px，不回到 56–72px。
- 触屏输入 / 选择器的文字保持 16px，避免 iOS 聚焦缩放；其他 chrome 标签 12–13px。
- 范围：展示站页头、页面标题与操作、资源 / 设置 / 组件页 tabs、搜索 / 筛选、侧栏导航 / 收藏 / 帮助 / 工作区 / 账号、分页、文档工具栏、Dialog / Drawer 的关闭按钮与 footer 操作。设置表单体内的输入 / 选择控件、Dialog 正文表单、组件用例与内容列表仍按各自密度和内容规则；后续纳入需单独记录。
- 设置页主题选择按内容成组：缩略图保持 16:10 比例，桌面靠右排列（6.25rem 一档，默认 100px），移动三等分；容器宽度达到 28rem 时使用行式布局，低于时回到堆叠，不把缩略图拉伸填满整行。
- 本条只维护运行尺度，不新增 token；正式发行需要时再由 F-01 决定语义变量与迁移。
